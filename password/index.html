Generate random passwords with browser security APIs

This generator creates passwords on the current device with the browser’s Web Crypto API. You control length, quantity and the allowed character categories. The page does not send generated values to UtilCover, but copied passwords still enter your system clipboard and should be stored with the same care as any other credential.

How to generate a secure random password

  1. Choose length and quantity. Password length can be 1–128 characters and the batch can contain 1–100 passwords. For an important account, prefer a long unique value that fits the site’s stated password rules.
  2. Select allowed categories. Enable uppercase letters, lowercase letters, numbers and special characters as required. The password must be at least as long as the number of selected categories because the generator guarantees each enabled category appears at least once.
  3. Generate, copy and save safely. Review the result, copy only what you need, and place it directly in a trusted password manager. Use a different password for each account and replace one promptly if it may have been exposed.

Practical password choices

A new account login

Select the categories accepted by the service and generate a long password that you do not reuse elsewhere. Save it in a password manager instead of changing characters in an old password or building a memorable pattern around the site name.

A Wi-Fi credential

Create a random value that the router and joining devices can enter. Excluding ambiguous characters such as 1, I, 0 and O can reduce transcription mistakes when someone must type the password from a printed card.

Several independent credentials

Increase the quantity when provisioning separate test accounts or devices. Each output is generated independently; do not treat the list as a sequence or assign one shared password to multiple real users.

Generation and security limits

  • The controls accept lengths from 1–128 and quantities from 1–100. A technically allowed short password may still be rejected by a service or be unsuitable for protecting an account.
  • Random indices come from crypto.getRandomValues. Rejection sampling avoids modulo bias when mapping 32-bit samples into a character set, and the final characters are shuffled with the same secure source.
  • Every selected category contributes at least one character. The remaining positions are sampled from the combined enabled set. Optional ambiguous-character removal filters 0oO1IiLl before generation.
  • The strength label is a local heuristic based on length and character variety, not a crack-time estimate or a guarantee. Account protections, reuse, phishing and storage practices also matter.
  • This page does not save a vault, synchronize credentials, check breach databases or verify a website’s policy. If Web Crypto is unavailable, secure generation stops rather than falling back to Math.random.

Password generator FAQ

How are the passwords randomized?

The browser supplies random 32-bit values through Web Crypto. The generator uses rejection sampling before selecting characters, includes one value from each enabled category and securely shuffles the finished password.

Does excluding ambiguous characters weaken a password?

It reduces the available alphabet slightly in exchange for easier manual reading. Length and uniqueness remain important. Leave the option off when values will always be copied and the receiving system accepts every character.

Is a “Strong” label a security guarantee?

No. The label is only a simple indication based on the generated text. It cannot account for password reuse, a compromised device, account recovery weaknesses or how the credential is stored.

Are generated passwords uploaded or saved?

No. Generation happens in the browser and the page has no account or storage feature. Copying places a value on the device clipboard, where other software or clipboard history may retain it.

Should I change passwords on a fixed schedule?

Change a password when it is exposed, reused, shared improperly or required by a confirmed security event. Predictable periodic changes can encourage weaker patterns; unique generated passwords and secure storage are more useful than arbitrary rotation.
