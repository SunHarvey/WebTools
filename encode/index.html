Encoding guide

Convert UTF-8 text or a URL component

Use the Base64 controls when a text-only field expects Base64, and use the URL controls when one query value or path component contains spaces, Unicode, or reserved punctuation. The input and result remain visible side by side, and Swap moves the result back into the input for a second operation.

How to encode or decode

  1. Identify the format.Enter ordinary UTF-8 text for encoding, standard Base64 text for Base64 decoding, or one URL component for percent encoding or decoding.
  2. Run one conversion.Choose Base64 encode, Base64 decode, URL encode, or URL decode. A malformed value produces an error instead of a partial result.
  3. Verify and copy.Inspect the result, optionally Swap it into the input to test a round trip, then copy only after confirming it matches the receiving system’s format.

Accepted formats and limitations

Base64 encoding accepts text, converts it to UTF-8 bytes, and emits the standard A–Z a–z 0–9 + / alphabet with padding. This is UTF-8 text Base64 only; it is not a file or arbitrary-binary decoder. Decoding removes whitespace and accepts optional omitted padding, but validates the alphabet and padding bits. It rejects Base64URL input containing - or _, malformed lengths, invalid Base64, and decoded non-UTF-8 bytes. Base64 is encoding, not encryption: anyone with a decoder can recover the text, so it provides no confidentiality.

URL operations directly use encodeURIComponent and decodeURIComponent. They percent-encode or decode a component such as one parameter value, not a full URL. Encoding an entire address would also escape its :, /, ?, =, and & structure. Decoding requires valid percent escapes and valid UTF-8 sequences; malformed input is rejected rather than guessed. No form-style conversion changes spaces into plus signs, and no Base64URL mode is available.

Encoding FAQ

Does Base64 hide or secure a secret?

No. Base64 changes how bytes are written so they can travel through text-oriented systems. It has no key and is immediately reversible. Use an appropriate encryption system, not Base64, when confidentiality is required.

Can I decode Base64 without the final equals signs?

Yes, optional omitted padding is accepted when the standard Base64 length can be completed unambiguously. Embedded whitespace is also ignored. The standard alphabet and canonical padding bits are still validated.

Why does a Base64 value fail after decoding bytes?

A syntactically valid Base64 sequence can represent arbitrary bytes. This page deliberately returns UTF-8 text only and rejects bytes that are not valid UTF-8, rather than silently inserting replacement characters.

Should I paste a complete web address into URL encode?

Usually not. The control applies component encoding, so paste only the individual value that will occupy a query parameter or path segment. Assemble the complete URL around that encoded value.
