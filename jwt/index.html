Inspect JWT structure without sending the token away

A JWT commonly stores a Base64URL-encoded JSON header and payload beside a signature segment. This page decodes the readable JSON and explains common time claims entirely in the browser. It does not contact an issuer, download keys or validate a signature.

How to decode a JWT

  1. Paste the compact tokenEnter a three-segment JWT. An optional Bearer prefix is removed before parsing. The input is limited to 64 KiB to keep browser processing bounded.
  2. Review header and payloadSelect “Decode JWT” to format both JSON objects. Check the declared algorithm, issuer, audience and subject against the system that produced the token.
  3. Interpret time claims carefullyThe inspector converts exp, nbf and iat NumericDate values into ISO and local time. These values are untrusted until the token has been cryptographically verified elsewhere.

Practical inspection examples

Debug an expired API session

Compare exp with the current time and inspect iat to understand when the token was issued. Clock differences and refresh-token behavior still need to be checked in the application.

Confirm issuer and audience values

Read iss and aud while troubleshooting configuration. Seeing the expected strings is useful for debugging but does not authenticate them.

Inspect a token from local logs

Decode a token without pasting it into an external service. Tokens may contain personal data or credentials, so remove them from logs and revoke exposed tokens when appropriate.

Security boundaries and limitations

  • This tool supports three-segment compact JWT/JWS input. It does not decrypt five-segment JWE tokens.
  • The signature segment is displayed as text but is not verified. The page does not accept secrets, public keys, certificates or remote JWKS URLs.
  • Header and payload must each decode to a UTF-8 JSON object. Malformed Base64URL, invalid UTF-8, arrays, null values and oversized input are rejected.
  • Time status is a convenience check using the current device clock. It does not apply issuer-specific clock skew, audience rules, revocation, nonce checks or authorization policy.
  • The page creates no storage entry and makes no network request after decoding. Browser extensions, clipboard history and the surrounding device remain outside the page's control.

JWT decoding questions

Can anyone read a JWT payload?

A normal signed JWT payload is encoded rather than encrypted, so anyone holding the token can usually decode its JSON. Do not place secrets in a payload unless a separate encryption design protects them.

Does a readable payload mean the token is valid?

No. Any party can construct readable Base64URL segments. Authenticity depends on signature verification with a trusted key plus checks for algorithm, issuer, audience, time and application policy.

Why is my token reported as not active?

The nbf claim is later than the current device time. Confirm the device clock, issuer clock and the verifier's permitted clock tolerance.

Is the pasted token uploaded or saved?

No. Parsing and display happen in the current browser. The tool does not send the token, store it in browser storage or add it to a history list.
