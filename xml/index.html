Format XML and check well-formedness

This XML formatter uses the browser's native DOMParser and XMLSerializer to process one complete XML document locally. Format mode creates readable indentation and reparses its own output before displaying it. Validate-only mode checks whether the document is well-formed without changing or returning a formatted copy. Your XML is not uploaded or sent to a server or third-party API, and the page does not retain recent input.

How to use the XML tool

  1. Paste one complete document.Use a single XML root element, with any XML declaration, comments, namespaces, attributes, and nested elements that belong in the document. XML fragments and multiple root elements are not accepted.
  2. Choose an action.Format & validate XML adds indentation where the document has element-only content. Validate XML only checks well-formedness and leaves the output area empty.
  3. Review the result and status.When the browser provides source coordinates, a syntax error reports its line and column without echoing the parser's raw diagnostic. Clear the page or leave it to erase the temporary input and output.

Practical XML examples

Format a compact service document

Paste <service><name>utilcover</name><enabled>true</enabled></service> and run Format & validate. Child elements are placed on separate indented lines, while the document is reparsed to make sure the generated output remains well-formed.

Check a namespaced document

Use Validate XML only for a document such as <feed xmlns="urn:example:feed">...</feed> when you want a syntax check without rewriting its visible source. Namespace bindings are parsed as XML names and namespace declarations, not as a schema.

Keep mixed content and preserved spaces

Content like <p>Keep <em>this</em> together</p> is kept inline so spaces around text are not reflowed. The formatter also respects xml:space="preserve" by serializing that element without inserting indentation inside it.

Supported XML, limits and formatting notes

The tool accepts one complete XML document and uses the browser's native XML parser. It checks well-formedness: matching element tags, quoted attributes, a single document element, and valid XML syntax. Error positions are shown only when the browser parser exposes a usable line and column. They are syntax locations, not a schema validation report.

To avoid DTD processing and keep parsing bounded, any DOCTYPE declaration is rejected before parsing. The tool does not validate DTDs or XSD schemas, resolve external references, fetch resources, or convert XML to JSON. A document that depends on a custom DTD entity therefore cannot be processed here. Use a dedicated XML application when schema validation or DTD-based entities are required.

Raw input is limited to 250,000 characters; the parsed document is limited to 20,000 nodes, including attributes, and a 100-level element nesting depth. Formatted output is limited to 500,000 characters. These limits bound browser work; they are not a promise that every device will process a maximum-sized document instantly.

Formatting is not byte-for-byte source preservation. The serializer may normalize empty-element syntax and namespace declarations. In element-only sections, whitespace-only text between child elements is normalized to create indentation. Mixed text content is kept inline, and xml:space="preserve" disables inserted whitespace for that element. If whitespace itself is application data, use that attribute or choose Validate XML only. Comments, processing instructions, CDATA and original quoting may be serialized in a normalized form.

Both the parser and serializer run in the page. The input and generated result are kept only in page memory, are not stored in browser storage or recent-tool history, and are cleared on page navigation or browser back/forward restoration.

XML formatter FAQ

Does this validate an XSD schema or DTD?

No. It checks XML well-formedness only. DTD declarations are intentionally rejected, and XSD validation is not implemented.

Can I format an XML fragment or several documents at once?

No. Each run accepts one complete XML document with a single root element. Wrap a fragment in a document element before using the tool.

Will formatting preserve every whitespace character?

No. Whitespace-only gaps between element children may be normalized for indentation. Mixed content remains inline, and an element with xml:space="preserve" is serialized without inserting new whitespace inside it. Use Validate XML only when you do not want a formatted result.

Is my XML uploaded or saved?

No. Parsing and formatting run locally in your browser. The page makes no request with the XML content, does not save it in browser storage or recent history, and clears the temporary page state when you leave.
