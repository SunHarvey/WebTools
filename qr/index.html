Make a static QR code for a URL, text or Wi-Fi

Create a QR code that contains exactly the information you enter, then download it as a PNG. Encoding and drawing happen in the browser, including Wi-Fi network names and passwords. The result is static: scanning returns the stored content directly rather than contacting UtilCover for a redirect.

How to generate a QR code

  1. Choose the content type. Use Text or URL for a web address, message or identifier. Choose Wi-Fi network to enter the SSID, security type, password and hidden-network setting in the standard Wi-Fi payload format.
  2. Set readable output options. Pick a PNG size, error-correction level and quiet zone. Keep strong contrast between the dark and light colors; a dark foreground on a light background is the safest starting point.
  3. Generate and scan-test. Download the PNG, then scan-test it with the devices and apps your audience will use. Verify URLs, wording and Wi-Fi details before printing or sharing, because the encoded content cannot be edited later.

Useful QR code examples

Share a complete web address

Paste the full https:// URL rather than a shortened label. A scanner can then open that exact address. Check spelling, query parameters and the final destination yourself; this generator does not visit or validate the website.

Let a guest join Wi-Fi

Select Wi-Fi mode and enter the network name exactly, including spaces and capitalization. Choose the matching WPA, WEP or open-network option. Anyone who can scan the image may be able to read or use the stored credentials, so share it accordingly.

Carry short offline text

Encode a reference number, event note or contact instruction that should be readable without a redirect service. Keep the payload concise when possible: denser QR matrices need more camera detail and more printed space.

Content, security and output limits

  • Text and URL input is limited to 2950 characters. Actual QR capacity also depends on UTF-8 byte length and the chosen error-correction level, so some content below that character count can still be too large.
  • Downloads are PNG only. The tool does not create SVG or PDF output, add a logo, build styled frames, shorten URLs, or place captions into the image.
  • Codes are static. There is no dynamic destination update, scan tracking, analytics, expiry control or account dashboard. To change the content, generate and distribute a new image.
  • Custom colors can reduce reliability. Preserve a clear quiet zone and strong foreground/background contrast; do not assume a code that looks attractive will scan on every camera, screen or printer.
  • Wi-Fi passwords are embedded in the QR payload, not encrypted by the image format. Treat a Wi-Fi QR code like a written credential and avoid posting private network access publicly.

QR code generator FAQ

Can I change the destination after downloading?

No. The text is encoded directly into a static QR matrix. There is no UtilCover redirect between the scanner and the content, so changing a URL or message requires a newly generated PNG.

Which error-correction level should I use?

Level M is a practical default for an unobstructed code. Higher levels add redundancy but also make the matrix denser for the same content. This tool does not support placing a logo over the modules, so avoid covering the code.

Why does my QR code fail to scan?

Check that the image has enough physical size, a clean quiet zone and strong contrast. Long content, glare, low-resolution printing or unusual colors can make scanning harder. Scan-test the final medium, not only the preview on this page.

Are Wi-Fi details sent anywhere?

No. The Wi-Fi payload is assembled and encoded in this browser. The downloaded QR code itself contains the credentials, however, so anyone with access to the image may scan them.
