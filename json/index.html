Format, check or compact strict JSON

Use this page when an API response, configuration value or copied data is difficult to read, or when you need to confirm that a string is valid JSON. Processing stays in the current browser tab. Format and Minify both parse the input with JSON.parse and serialize it again with JSON.stringify, so the output can differ from the source beyond whitespace.

How to use the JSON formatter

  1. Paste strict JSON into Input JSON. Objects, arrays, strings, numbers, booleans and null are accepted, including a top-level primitive.
  2. Choose an action. Format adds two or four spaces of indentation, Minify removes unnecessary whitespace, and Validate checks the input without producing a transformed copy.
  3. Read the status before copying. A successful format or minify operation appears in Result. If parsing fails, correct the source and try again; the tool does not guess what malformed input was meant to say.

Practical examples

Review an API response

A one-line response such as {"ok":true,"items":[1,2]} is valid but awkward to scan. Format it to make nested arrays and objects visible before debugging a request or discussing the payload with a teammate.

Prepare compact configuration data

After editing a JSON configuration, validate it first and then minify it when a system expects a compact string. Minification emits a new JavaScript serialization rather than preserving the exact source text, so review the transformation limits below when exact key or number representation matters.

Check copied values safely

Use Validate to distinguish strict JSON from a JavaScript object literal. Keys and string values require double quotes, and trailing commas are not permitted. Input is parsed as data with JSON.parse, never executed as JavaScript.

Format and validation limits

  • This is a strict JSON formatter, validator and minifier. It does not repair missing quotes or commas, provide schema validation, highlight syntax, or report exact line and column numbers.
  • Parsing and serialization are not lossless text operations. Duplicate keys collapse to the last value, and integer-like keys can change property order when JavaScript serializes the object.
  • JSON numbers become JavaScript Number values. Number precision is limited beyond the safe integer range; numeric spellings can be normalized, including -0 to 0. Use a lossless JSON parser when exact large numbers or source representation must be retained.
  • JSON5 features are not supported. Comments, trailing commas, single-quoted strings, unquoted property names, NaN and Infinity will fail strict parsing.
  • Input is pasted as text; there is no file upload or file picker. Very large documents are limited by the memory and responsiveness of your browser tab, so use a local command-line parser for unusually large datasets.
  • Formatting cannot detect whether a valid value is correct for your application. A valid date string, identifier or number may still violate the rules of the API that receives it.

JSON formatter FAQ

Does formatting change the JSON data?

It can. Formatting parses the text into JavaScript values and serializes those values with indentation. Most ordinary input represents the same application data afterward, but duplicate keys, property order, large-number precision and number representation can change as described above.

Can this fix invalid JSON automatically?

No. The status reports that parsing failed, but the tool does not insert quotes, remove comments or otherwise repair the source. Automatic repair can hide the real error, so corrections remain under your control.

Does it support JSON5 or JavaScript object literals?

No. The parser follows the JSON syntax accepted by JSON.parse. Convert comments, single quotes, trailing commas and other JavaScript-only syntax before using this page.

Is pasted JSON sent to UtilCover?

No. Formatting, minification and validation run in your browser. Avoid copying sensitive results to a shared clipboard or leaving them visible on an unattended device.
