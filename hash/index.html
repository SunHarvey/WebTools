Calculate and verify a SHA checksum

This calculator creates a repeatable hexadecimal integrity fingerprint for text or one local file. Choose SHA-256, SHA-384 or SHA-512 to match the algorithm named by a download publisher, build pipeline or data specification. Everything runs through the browser's Web Crypto API, so the input is not sent to this site.

How to use the hash calculator

  1. Choose the matching algorithmSelect SHA-256, SHA-384 or SHA-512. The algorithm must match before two digests can be checked; equal digests do not by themselves prove that the inputs were identical.
  2. Hash text or one fileEnter text and choose “Hash text,” or select a file up to 32 MiB and choose “Hash file.” The two input paths are separate, so the selected action determines what is processed.
  3. Copy or compare the resultCopy the lowercase hexadecimal output, or paste a published checksum into the expected field and compare. A match establishes digest equality under that algorithm and is strong integrity evidence when the expected value is trusted, but it is not proof of identical bytes or authorship.

Practical checksum examples

Verify a downloaded archive

If a software publisher lists a SHA-256 checksum, select the downloaded file and SHA-256, then compare the two strings. Matching digests are strong evidence that the download has not changed when the published value is trustworthy. They are not mathematical proof of identical input because hash collisions are possible.

Confirm text passed between systems

Hash a configuration fragment, API sample or release note with the algorithm required by the receiving system. Text is encoded by TextEncoder as UTF-8 before hashing, so capitalization, spaces, line endings and invisible characters all affect the result.

Record a build artifact fingerprint

Create a SHA-512 or SHA-384 fingerprint for a small package before moving it between machines. Recalculate it later to detect changed bytes. Keep the algorithm name beside the digest; a bare hexadecimal string does not identify which SHA variant produced it.

Behavior and limitations

  • File hashing calls arrayBuffer() and buffers the whole selected file in memory before Web Crypto processes it. It is not incremental. The 32 MiB cap limits memory use and means larger files need another checksum program.
  • Text hashing uses the exact UTF-8 bytes returned by TextEncoder. The tool does not normalize Unicode, whitespace or line endings, so visually similar text can legitimately produce a different digest.
  • Comparison will trim surrounding whitespace and lowercase both strings only. It does not validate the expected digest's hexadecimal format or length; two identical nonempty strings can compare as equal even when they are not valid digests.
  • If asynchronous calculations overlap, the latest request wins in the UI. An older operation may finish, but it cannot replace the output or status from the newer request.
  • A cryptographic hash is an integrity fingerprint, not encryption, authentication or password hashing. It cannot recover input, prove an author's identity, make an untrusted checksum trustworthy or safely store a human password.

SHA checksum questions

Which SHA algorithm should I choose?

Use the exact algorithm specified by the source you are checking. SHA-256 output cannot match SHA-384 or SHA-512 output for the same input. When no external requirement exists, SHA-256 is a common integrity-check choice, but this page does not choose a protocol for you.

Why did a tiny text edit change the entire hash?

Digest functions are designed so a small byte change creates a very different output. Check spaces, final newlines, character case and line-ending style. The visible characters alone do not reveal every UTF-8 byte that was hashed.

Does a matching checksum prove a download is safe?

No. It shows digest equality under the chosen algorithm, which is useful integrity evidence but does not eliminate collision risk. If an attacker can replace both the file and the published checksum, the comparison offers no source authentication, and it does not scan content for malware.

Does hashing upload or save my input?

The calculation is performed locally with Web Crypto. This tool adds no network request, tracking or storage for the entered text, selected file or result. Browser extensions and the surrounding device remain outside what the page can guarantee.
