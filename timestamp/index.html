Unix time guide

Convert epoch values and local dates

A Unix timestamp records elapsed time relative to the Unix epoch. This page shows the same instant as whole Unix seconds, normalized milliseconds, ISO 8601 UTC, and a formatted browser-local time. It also converts a value entered through the local date-and-time control back to epoch units.

How to convert a timestamp

  1. Enter one side.Paste a numeric Unix value and select Auto, Seconds, or Milliseconds, or choose a wall-clock value in the local date field.
  2. Convert and inspect.Run the matching conversion, then compare seconds, milliseconds, ISO UTC, and local output. The displayed timezone identifies the browser setting used for local formatting.
  3. Copy the required form.Use the copy button beside the exact representation your log, API, database, or test fixture expects; do not substitute seconds for milliseconds.

Detection, rounding, and timezone limits

Auto detection uses one fixed rule: when the numeric absolute value is below 100,000,000,000, it is seconds; otherwise milliseconds. An explicit unit selection overrides that rule. This threshold is convenient for modern timestamps but cannot infer the intended unit from context. Fractional milliseconds normalize through JavaScript Date to the integer millisecond it stores. The seconds output applies Math.floor to normalized milliseconds divided by 1,000, including negative values, so -1 millisecond maps to second -1.

The datetime-local field has no offset. Its value is interpreted in the browser local timezone. ISO output is always UTC and ends in Z; the local output uses the browser’s locale and timezone. There is no timezone selector and no DST disambiguation control, so ambiguous or skipped wall-clock times around daylight-saving transitions follow browser Date behavior. Use a source with an explicit offset when that distinction matters.

Inputs must be finite numeric values and must fit the browser Date range. Very large epoch values fail instead of producing a fabricated date. The tool supports seconds and milliseconds only, not microseconds or nanoseconds, and it does not preserve fractional precision below a millisecond.

Unix timestamp FAQ

How does Auto decide seconds versus milliseconds?

It compares the absolute numeric value with 100,000,000,000. Values below the threshold are multiplied by 1,000 as seconds; values at or above it are passed to Date as milliseconds.

Why is local time different from the ISO value?

They describe the same instant. ISO is rendered in UTC, while local time uses the timezone and locale reported by your browser. The offset changes the clock display, not the underlying epoch value.

What happens to fractional or negative timestamps?

Date first truncates fractional milliseconds toward zero. Whole Unix seconds are then calculated with floor. When the normalized millisecond value remains negative, such as -1 through -999, the result is second -1; a value such as -0.999 millisecond normalizes to 0 and returns second 0.

Can I choose another timezone or resolve a DST overlap?

No. The page has no timezone selector or DST disambiguation. Change the source to include a known offset and verify it elsewhere when a particular regional interpretation is required.
