Convert CSV, TSV and JSON locally

This browser-based CSV converter handles quoted fields rather than splitting rows on punctuation. It supports explicit comma or tab delimiters, optional headers, and conversions in both directions. CSV values remain strings; JSON numbers are preserved as their original source text instead of being rounded through JavaScript numbers. Input, output and structure are bounded, and the page does not upload or retain your data.

How to use the CSV / TSV converter

  1. Choose a direction and delimiter.Select CSV / TSV to JSON or JSON to CSV / TSV, then explicitly choose comma or tab. The tool does not guess the delimiter. For CSV input, choose whether the first record contains headers.
  2. Paste one table or JSON array.Paste plain text into the input. Quoted CSV fields can contain commas, tabs, doubled quotes and embedded line breaks. Use one consistent number of fields in every CSV record when headers are enabled.
  3. Convert, review and copy.Run the conversion and inspect the output before copying it. Errors are localized and do not echo your input. Clear the page or navigate away to erase temporary values from memory.

Practical CSV and JSON examples

Keep leading zeroes and boolean-looking values

With code,active followed by 007,true, CSV-to-JSON returns {"code":"007","active":"true"}. Every CSV cell remains a string; the converter does not infer numbers, booleans, dates or null values. This avoids changing identifiers and spreadsheet-like text during conversion.

Convert quoted fields with commas and line breaks

A field such as "said ""hello, world""" decodes to said "hello, world". A quoted field may span physical lines; its embedded line break stays inside that cell instead of creating an extra record. The reader accepts CRLF, LF and CR record breaks.

Export a flat JSON object array

[{"name":"Ada","code":7},{"name":"Lin","active":true}] becomes a CSV table with the first-seen property names as headers. Missing properties become blank fields. Scalar values are written as text, and numeric source text is preserved exactly, including large integer digits.

Supported data, validation and limits

For CSV-to-JSON, the delimiter must be selected as comma or tab. The parser supports quoted fields, doubled quotes, separators inside quoted fields, and embedded line breaks. It accepts CRLF, LF and CR record separators. With the header option enabled, header names must be unique and non-empty, and each record must have the same number of fields. With headers disabled, rows become arrays instead of objects. No type guessing is performed.

JSON-to-CSV accepts only a top-level array of flat objects. Nested arrays and objects are not supported and produce an explicit error rather than being flattened or silently discarded. Empty or duplicate JSON property names are rejected because they cannot become reliable CSV headers. Properties are collected in first-seen source order; a missing property becomes a blank field. JSON strings are decoded as text, booleans and null become the words true, false and null, and number tokens are preserved from the JSON source so JavaScript floating-point rounding does not alter large digits.

Limits apply before conversion: raw input is at most 250,000 characters, the CSV record budget is 10,000 records including a header row, each record has at most 256 columns, and the aggregate is at most 20,000 cells. JSON nesting is limited to 100 levels, and serialized output is capped at 500,000 characters. A limit error clears stale output. These bounds limit browser work; they do not promise that every device will process maximum-sized input instantly.

The output is ordinary CSV text, not a spreadsheet-specific safety transformation. CSV quoting preserves field boundaries but does not make formula-like values harmless in spreadsheet software. Some spreadsheet apps may interpret values beginning with formula markers as instructions. Review data from untrusted sources before opening the output in a spreadsheet; this tool deliberately does not rewrite cell values or claim formula sanitization.

Everything runs in the page with local JavaScript. No CSV or JSON input is uploaded, sent to an API, written to browser storage, or added to recent-tool history. There is no file upload. Input, output and selected options are cleared on the Clear button, when you leave the page, and when a page is restored through browser history.

CSV / TSV converter FAQ

Does the converter guess whether my delimiter is a comma or tab?

No. Select comma for CSV or tab for TSV before running. The selected delimiter is applied to both input and output so a conversion never depends on automatic guessing.

Are CSV numbers converted to JSON numbers?

No. CSV cells always remain strings, so values such as 007, true and date-like text are preserved as text. JSON-to-CSV also writes scalar values as cell text and preserves numeric source tokens.

Can JSON with nested objects or arrays be converted?

No. JSON-to-CSV accepts a top-level array of flat objects only. A nested array or object is rejected with an explicit message; the converter does not silently flatten it.

Is the CSV output safe to open in a spreadsheet?

This is plain CSV, not a formula sanitizer. Spreadsheet programs may interpret formula-like cell contents. Review untrusted values before opening the file, and do not treat CSV quoting as a security transformation.

Is my input uploaded or saved?

No. Conversion happens locally in your browser. The page sends no data to a server or third-party API, does not save content in browser storage or recent-tool history, and clears temporary input and output on navigation.
