Format YAML and convert configuration data

YAML is commonly used for human-edited configuration. This local YAML formatter checks one document at a time, reprints parsed YAML, and converts between YAML and JSON. The parser and serializer run from a bundled browser file on this site; this tool does not upload your text to a server or third-party API.

How to use the YAML tool

  1. Paste one document.Enter YAML, or select the JSON-to-YAML action and paste strict JSON. The input limit is 250,000 characters.
  2. Choose an action.Format & validate YAML to normalize indentation, convert YAML to JSON for a JSON representation, or convert JSON to YAML.
  3. Review before using the result.Syntax errors include a line and column when the parser provides a source mark. Copy only the result you intend to keep; clearing or leaving the page erases the current input and output.

Practical YAML examples

Format a service configuration

Paste a mapping such as service: api with a nested port and enabled flag. Formatting makes the structure easier to scan and reports indentation or syntax errors without trying to guess a repair.

Convert configuration to JSON

Use YAML to JSON when an application, API or test fixture needs JSON. The result is a JavaScript representation serialized as JSON, so JSON’s string-key and value rules apply; inspect conversions involving unusual mapping keys or YAML-specific constructs.

Turn JSON into readable YAML

Paste strict JSON and choose JSON to YAML to produce an indented document. This is useful for reviewing configuration changes or preparing a small example, but it does not add application-specific defaults or validate a schema.

Supported syntax, limits and conversion notes

This page uses the locally bundled js-yaml parser with a JSON-compatible schema and YAML 1.2 scalar rules. It accepts one document per run and supports JSON-compatible strings, numbers, booleans, nulls, arrays and mappings. YAML 1.1-only types, custom tags, multi-document streams, and non-finite floats such as Infinity and NaN are rejected because JSON has no representation for them. Plain values such as on are handled using YAML 1.2 rules rather than older YAML 1.1 boolean conventions.

To bound browser work, raw input is limited to 250,000 characters; parsed output is limited to 20,000 values, 64 aliases, and 100 levels of collection nesting. These are rejection limits, not a guarantee that every device will process a maximum-sized document instantly. Use a local command-line parser for larger or operationally critical files.

Formatting parses and serializes the document, so it is not a lossless source editor: comments and original spacing are removed, and style choices may change. YAML mapping keys are represented as JavaScript object properties; JSON can only represent string property names, so non-string YAML keys may be converted to strings. Review the result if those distinctions matter.

JSON-to-YAML accepts strict JSON only; comments, trailing commas and unquoted object keys are not accepted. This tool does not perform Kubernetes, GitHub Actions, Docker Compose or other schema validation, does not resolve external references, and does not determine whether a syntactically valid configuration is safe for a particular system. Input and output remain in page memory only; no network request is made with your content, and the page does not store recent input.

YAML formatter FAQ

Does formatting preserve YAML comments?

No. The parser converts the document to values and serializes those values again, so comments and original spacing are removed. Keep a separate copy of the source when comments or exact formatting are important.

Does this validate Kubernetes or GitHub Actions schemas?

No. It checks supported YAML syntax and converts JSON-compatible values. Application-specific fields, resource constraints, permissions and deployment behavior are not validated.

Can I paste a multi-document YAML stream?

No. Each run accepts a single document. Separate a stream into individual documents before checking it with this page.

Is my configuration uploaded?

No. The parser bundle is hosted with this site and runs locally in your browser. Input and output are not sent to UtilCover or an external API and are cleared when you leave the page.
