时间戳说明

在纪元数值与所选时区日期之间转换

Unix 时间戳以纪元为基准记录经过的时间。本页把同一时刻显示为整数秒、归一化毫秒、ISO 8601 UTC 和所选时区时间；日期控件中的钟表时间也会按所选时区解释后转为纪元数值。

三步完成时间转换

  1. 选择输入方向。可以粘贴数字时间戳并指定单位，也可以输入一个钟表日期并选择该日期所属的时区。
  2. 执行并对照结果。转换后同时检查秒、毫秒、UTC 与所选时区显示。修改选择器会更新显示；转换日期时则会按该时区解释输入。
  3. 复制正确单位。根据接口、数据库或日志字段的约定，复制对应结果。秒和毫秒相差一千倍，不能只凭数字长度随意替换。

明确解释小型测试数据

1000 在自动模式中会被当作秒；显式选择毫秒则覆盖自动判断，结果变成纪元后一秒。旧日期和人工构造的夹具尤其应该指定单位。

自动判断、精度与时区限制

自动检测只有一条规则：数字绝对值小于 100,000,000,000 时按秒处理，否则按毫秒处理。显式选择秒或毫秒单位会覆盖该规则。这个阈值适合常见的现代日期，却无法从上下文判断很早的毫秒值或很远的秒值，因此有歧义时不要依赖自动模式。

小数毫秒会通过 JavaScript Date 归一化为它实际保存的整数毫秒。之后用归一化毫秒除以一千，并向下取整得到秒数；规则同样用于负数，所以纪元前一毫秒对应秒值 -1，而不是零。超过浏览器 Date 支持范围的巨大数值会报错，不会生成看似正常的日期。显式微秒和纳秒输入使用 BigInt 按整数解析，因此显示的精确值可保留毫秒以下精度；日期与 ISO 渲染仍采用浏览器支持的整数毫秒。

datetime-local 本身不含偏移量，因此本页会把输入的钟表时间按所选“输入与显示时区”解释。Intl 提供地区偏移和夏令时规则：夏令时跳变中不存在的时间会被拒绝；重叠时刻则采用较早的匹配瞬间。ISO 输出始终使用 UTC 并以 Z 结尾。本页不自行维护时区数据库，历史规则以浏览器提供的数据为准。

常见问题

自动模式怎样判断秒和毫秒？

它比较绝对值与 100,000,000,000。低于阈值就乘以一千作为秒，高于或等于阈值则直接作为毫秒交给 Date。

为什么 ISO 与所选时区的钟点不同？

两者表示同一瞬间。ISO 使用 UTC，所选时区结果则应用该地区的偏移；改变的是钟表显示，不是底层 Unix 数值。

负数或小数会怎样处理？

Date 会先把小数毫秒朝零截断，再向下取整计算整数秒。归一化后的毫秒值仍为负数时，例如 -1 到 -999 毫秒，秒值是 -1；-0.999 毫秒会先归一化为 0，因此秒值也是 0。

夏令时空缺和重叠如何处理？

Intl 会应用所选地区的规则。向前跳变中不存在的钟表时间会被拒绝；向后回拨时若同一钟点出现两次，转换器会稳定选择较早的瞬间。
