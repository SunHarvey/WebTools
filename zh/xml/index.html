XML 格式化与校验工具

在浏览器本地格式化一个 XML 文档，并检查其格式是否良构。

XML 内容只在当前浏览器中处理，不会上传、保存或加入最近使用记录。

本地格式化 XML 并检查文档良构性

本 XML 格式化工具使用浏览器原生 DOMParser 与 XMLSerializer，在本地处理一个完整 XML 文档。格式化模式会生成易读缩进，并在显示结果前再次解析输出；仅校验模式只检查文档是否良构，不修改或返回格式化副本。XML 内容不会上传或发送到服务器或第三方 API，页面也不会保存最近输入。

如何使用 XML 工具

  1. 粘贴完整文档。输入一个 XML 根元素，以及文档所需的 XML 声明、注释、命名空间、属性和嵌套元素。不接受 XML 片段或多个根元素。
  2. 选择操作。“格式化并校验 XML”会为仅含元素的内容添加缩进；“仅校验 XML”只检查格式良构性，并保持输出区域为空。
  3. 检查结果和状态。如果浏览器提供源代码位置，语法错误会显示行号与列号，但不会回显解析器的原始诊断。离开页面或点击清除后，当前输入和输出会清除。

XML 工具的实际用法

格式化紧凑的服务文档

输入 <service><name>utilcover</name><enabled>true</enabled></service> 并运行“格式化并校验”。子元素会显示在独立缩进行，随后工具会重新解析生成的结果，确认输出仍是良构 XML。

检查带命名空间的文档

如果只想检查语法而不重写可见源文本，可选择“仅校验 XML”，例如 <feed xmlns="urn:example:feed">...</feed>。命名空间会作为 XML 名称和声明解析，但不会据此执行任何模式校验。

保留混合内容和空白

<p>保留 <em>这段文字</em> 连在一起</p> 这样的混合内容会保持在同一行，避免改动文字周围的空格。工具也会遵循 xml:space="preserve"，不在该元素内部插入缩进空白。

支持范围、资源限制与格式说明

工具接受一个完整 XML 文档，并调用浏览器原生 XML 解析器检查良构性，包括标签是否匹配、属性是否加引号、是否只有一个文档元素以及 XML 语法是否有效。只有在浏览器解析器提供可识别的行号和列号时，错误状态才会显示位置。这只是语法定位，不是模式校验报告。

为了避免处理 DTD 并限制浏览器解析成本，工具会在解析前拒绝任何 DOCTYPE 声明。当前不支持 DTD 或 XSD 校验，不解析外部引用、不获取网络资源，也不提供 XML 转 JSON。依赖自定义 DTD 实体的文档无法在此处理；若需要模式校验或 DTD 实体，请使用专门的 XML 应用。

原始输入最多 250,000 个字符；解析后的文档最多 20,000 个节点（包含属性），元素嵌套最多 100 层；格式化输出最多 500,000 个字符。这些上限用于控制浏览器工作量，并不代表所有设备都能瞬间处理达到上限的文档。

格式化并非逐字节保留源文件。序列化器可能会规范化空元素语法和命名空间声明。在仅含元素的区域，元素之间的纯空白文本会被规范化以便缩进；混合文本内容会保持同行，且 xml:space="preserve" 会禁止在对应元素内部插入新空白。如果空白本身属于应用数据，请设置该属性或只运行“仅校验 XML”。注释、处理指令、CDATA 和原有引号样式也可能被重新序列化。

解析与格式化都在当前页面运行。输入和生成结果只保留在页面内存中，不写入浏览器存储或最近工具记录；离开页面以及浏览器前进或后退恢复页面时，临时状态都会清除。

XML 格式化常见问题

这个工具会校验 XSD 模式或 DTD 吗？

不会。它只检查 XML 良构性。工具会主动拒绝 DTD 声明，目前也没有实现 XSD 校验。

可以格式化 XML 片段或一次处理多个文档吗？

不可以。每次运行只接受一个包含单一根元素的完整 XML 文档。使用前请先将片段放入根元素中。

格式化会保留所有空白字符吗？

不会。元素子节点之间仅含空白的文本可能会被规范化为缩进。混合内容会保持同行；带有 xml:space="preserve" 的元素内部不会插入新的空白。如果不希望生成格式化结果，请选择“仅校验 XML”。

我的 XML 会被上传或保存吗？

不会。解析和格式化在浏览器本地运行。页面不会把 XML 内容放入网络请求、浏览器存储或最近使用记录，并会在离开页面时清除临时状态。
