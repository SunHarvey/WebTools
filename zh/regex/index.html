无需上传文本即可测试正则表达式
此工具使用浏览器内置的 JavaScript RegExp 引擎，在一次性的独立 Worker 中运行表达式。它会高亮匹配内容、列出编号捕获组和命名捕获组，并按照 JavaScript 的替换规则生成预览。正则、日志、代码片段、业务文本和替换结果都只保留在当前标签页中，离开页面时会清除。

常见正则测试场景

      
提取结构化字段
测试标识符、日期、类似邮箱的字符串或日志字段。通过捕获组可以确认每一段匹配内容之后会如何被脚本或编辑器使用。

      
检查搜索和迁移规则
在编辑器、命令行脚本或迁移任务中正式使用前，先粘贴具有代表性的配置、代码和文案。除了应该匹配的内容，也应加入不应匹配的反例，以便发现范围过宽的问题。

      
预览批量替换
提前检查 $1 等编号捕获组、表示完整匹配的 $&，以及 $<name> 形式的命名捕获组，确认无误后再到原文件中执行修改。

    

    
JavaScript 正则规则与安全限制
    
      
  • 工具使用当前浏览器的 JavaScript RegExp 实现，不会模拟 PCRE、.NET、Python 或 RE2。不同引擎的语法、转义和断言能力可能不同。
    • 
      
  • 支持 g、i、m、s、u 和 y 标志。只有 g 会继续查找多个匹配；y 控制粘连起点，也可以与 g 组合。
    • 
      
  • 某些表达式会发生灾难性回溯。为了避免整个页面长时间无响应，每次计算都会启动新的 Worker，超过 500 毫秒后立即终止，而不是继续占用主线程。
    • 
      
  • 表达式限制为 2,000 个字符，测试文本限制为 200,000 个字符，替换内容限制为 2,000 个字符。最多接受 1,000 个匹配项和 50 个捕获组；匹配与捕获组数据总量、替换结果分别限制为 500,000 个字符。
    • 
      
  • 为了控制页面节点数量，页面最多高亮 200 个匹配项，并在详情达到 1,000 行时停止渲染；匹配总数仍可统计最多 1,000 个已接受匹配。零长度匹配会用可见符号标识。
    • 
      
  • 输入不会写入 localStorage、sessionStorage、Cookie、浏览器历史或最近工具列表。离开页面时会清空输入、输出、导航状态和 Worker 内存。
    • 
      
  • 高亮和详情均通过安全文本节点显示，不会把测试内容当作 HTML 执行。复制操作只会在用户主动点击复制按钮时发生。
    • 
    

    
正则表达式测试常见问题

      
工具会上传表达式或测试文本吗？
不会。页面不会把正则、测试文本或替换内容发送到远程 API。独立 Worker 也从同一站点加载，全部计算都发生在浏览器内部。

      
为什么表达式被强制停止？
如果 500 毫秒内仍未完成，Worker 会被终止以保护当前标签页。可以减少嵌套量词、缩小含糊的备选分支，或使用更小但仍有代表性的输入进行测试。

      
为什么只显示一个匹配项？
需要查找多个结果时应启用全局 g 标志。粘滞 y 标志并不等同于全局搜索，因为下一次匹配必须正好从当前索引开始。

      
可以用它完整验证邮箱或网址吗？
它可以帮助测试表达式和样本，但单个正则通常不能覆盖复杂标准的全部规则。正式验证时应优先使用最终系统对应的解析器或业务校验逻辑。
