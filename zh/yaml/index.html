格式化 YAML 并转换配置数据

YAML 常用于人工编写的配置文件。本工具在本地检查单个文档的语法、重新排版 YAML，并提供 YAML 与 JSON 的互相转换。解析器和序列化器作为本站脚本随页面本地加载；工具不会把输入上传到服务器或第三方 API。

如何使用 YAML 工具

  1. 粘贴一个文档。输入 YAML；如需从 JSON 转换，请先选择“JSON 转 YAML”再粘贴严格格式的 JSON。输入上限为 250,000 个字符。
  2. 选择操作。“格式化并校验 YAML”会规范缩进并检查语法；“YAML 转 JSON”生成 JSON 表示；“JSON 转 YAML”则将 JSON 重新排成 YAML。
  3. 检查结果再使用。解析器提供源位置时，语法错误会显示行号和列号。本地复制结果后再用于其他系统；清除或离开页面会删除当前输入和输出。

YAML 实用示例

整理服务配置

可以粘贴包含 service: api、嵌套端口号和 enabled 布尔值的映射。格式化可让层级更易阅读；若语法不正确，工具会报告问题，而不会擅自猜测并修复内容。

将配置转换为 JSON

当应用接口、测试样例或其他系统需要 JSON 时，可使用 YAML 转 JSON。结果由 JavaScript 数据表示序列化而成，必须遵循 JSON 的键和值规则；如果 YAML 使用特殊键或仅适用于 YAML 的结构，请仔细核对转换结果。

将 JSON 转为易读 YAML

粘贴严格 JSON 并选择 JSON 转 YAML，即可得到缩进后的文档。这适合审阅配置变更或准备小型示例；它不会自动补充应用默认值，也不会替你验证特定产品的配置模式。

支持范围、大小限制与转换说明

本页使用本地打包的 js-yaml 解析器，并按照 YAML 1.2 与 JSON 兼容值规则处理。每次只接受单个文档，支持 JSON 可表达的字符串、数字、布尔值、空值、数组和映射。YAML 1.1 专有类型、自定义标签、多文档流以及 Infinity（无穷大）和 NaN（非数值）等非有限浮点数会被拒绝，因为 JSON 无法表示它们。像 on 这样的普通值按 YAML 1.2 规则处理，不会误判为旧版 YAML 1.1 布尔值。

为限制浏览器处理量，原始输入最多 250,000 个字符；解析后最多 20,000 个值、64 个别名和 100 层集合嵌套。达到上限时，工具会拒绝处理。设备性能不同，大文档耗时也会不同；特别大的文件或生产关键配置建议使用本地命令行解析器。

格式化会先解析再重新序列化，因此它不是保留源文件原样的编辑器：注释和原有空白会被移除，标量的书写风格也可能改变。YAML 映射键会转换成 JavaScript 对象属性，而 JSON 只支持字符串属性名，因此非字符串 YAML 键可能会转为字符串。如果这类差异会影响程序行为，请不要直接使用未经核对的转换结果。

JSON 转 YAML 只接受严格 JSON，不接受注释、尾随逗号或未加引号的对象键。本工具不执行 Kubernetes、GitHub Actions、Docker Compose 等配置模式校验，不解析外部引用，也不判断一份语法正确的配置对特定系统是否安全。输入和结果仅存在于页面内存中；用户内容不会发起网络请求，也不会写入最近使用记录。

YAML 工具常见问题

格式化会保留 YAML 注释吗？

不会。工具会把文档解析为数据值，再重新生成 YAML，因此注释和原有空白会被移除。如果注释或原始格式很重要，请另外保留源文件。

能校验 Kubernetes 或 GitHub Actions 配置模式吗？

不能。本工具只检查支持范围内的 YAML 语法，并转换 JSON 兼容值；不会校验应用字段、资源限制、权限或部署行为。

可以粘贴包含多个文档的 YAML 流吗？

不可以。每次只处理单个文档；请先拆分文档，再分别使用本工具检查。

我的配置会上传吗？

不会。解析器脚本随本站页面本地提供，并在浏览器中执行。输入和结果不会发送到 UtilCover 或外部 API，离开页面时会清除。
