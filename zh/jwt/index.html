无需发送令牌即可检查 JWT 结构

JWT 通常由 Base64URL 编码的 JSON Header、Payload 和签名段组成。本页面只在浏览器中解码可读 JSON，并解释常见时间声明；不会联系签发方、下载密钥或验证签名。

JWT 解码方法

  1. 粘贴紧凑格式令牌输入由三个部分组成的 JWT。开头可以带有 Bearer 前缀，解析前会自动移除。输入上限为 64 KiB，以限制浏览器资源占用。
  2. 检查 Header 和 Payload点击“解码 JWT”后，两段 JSON 会格式化显示。请根据产生令牌的系统核对算法、签发方、受众和主体。
  3. 谨慎理解时间声明工具会把 exp、nbf 和 iat NumericDate 转换为 ISO 时间和本地时间。在其他位置完成加密验证之前，这些值仍是不可信输入。

常见检查场景

排查 API 会话过期

把 exp 与当前时间比较，并通过 iat 了解签发时间。仍需在应用中检查设备时钟差异和刷新令牌流程。

核对签发方和受众

排查配置时查看 iss 和 aud。看到预期字符串有助于调试，但不能认证这些内容确实来自可信签发方。

检查本地日志中的令牌

不必把令牌粘贴到外部服务即可解码。令牌可能包含个人信息或访问凭据；应从日志中删除，并在发生暴露时及时撤销。

安全边界与限制

  • 本工具支持三段式 JWT/JWS 紧凑格式，不会解密五段式 JWE。
  • 页面只显示签名段，不执行验证，也不接收密钥、证书或远程 JWKS 地址。
  • Header 和 Payload 必须解码为 UTF-8 JSON 对象。错误的 Base64URL、无效 UTF-8、数组、null 和超限输入都会被拒绝。
  • 时间状态只按照当前设备时钟提供辅助判断，不处理签发方允许的时钟偏差、受众规则、撤销、nonce 或授权策略。
  • 解码后不会写入浏览器存储，也不会新增网络请求。浏览器扩展、剪贴板历史和设备环境不属于页面能够控制的范围。

JWT 解码常见问题

任何人都能读取 JWT Payload 吗？

普通签名 JWT 的 Payload 是编码而不是加密，因此持有令牌的人通常都能解码其中的 JSON。除非另有加密设计保护，否则不要把秘密写入 Payload。

能正常解码就代表令牌有效吗？

不是。任何人都可以构造可读的 Base64URL 内容。真实性取决于使用可信密钥验证签名，并核对算法、签发方、受众、时间和应用策略。

为什么提示令牌尚未生效？

nbf 声明晚于当前设备时间。请检查设备时钟、签发方时钟以及验证端允许的时间偏差。

粘贴的令牌会上传或保存吗？

不会。解析和显示只在当前浏览器中执行，本工具不会发送令牌、写入浏览器存储或创建历史记录。
