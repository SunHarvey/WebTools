JSON 格式化与验证工具

即时格式化、压缩和验证 JSON，所有数据仅在浏览器中处理。

您的 JSON 仅保留在当前浏览器中，绝不会上传。

就绪
安全解析：使用 JSON.parse 和 JSON.stringify，绝不会将输入作为代码执行。

整理、校验或压缩严格 JSON

接口返回值、配置片段或复制来的数据挤在一行时，可以先在这里整理缩进；提交数据前，也可以检查它是否符合严格 JSON 语法。所有操作都在当前浏览器标签页完成。“格式化”和“压缩”都会先用 JSON.parse 解析，再用 JSON.stringify 重新序列化，因此输出与原文的差异可能不止空白。

使用方法

  1. 把严格 JSON 粘贴到输入框。对象、数组、字符串、数字、布尔值和 null 都可以作为顶层内容。
  2. 选择需要的操作。“格式化”可按 2 个或 4 个空格缩进；“压缩”会去掉无意义空白；“验证”只检查语法，不生成转换后的文本。
  3. 确认状态后再复制。格式化或压缩成功时，结果会出现在右侧。解析失败时请回到原文修正；本工具不会猜测错误内容原本想表达什么。

常见使用场景

查看接口返回数据

像 {"ok":true,"items":[1,2]} 这样的单行内容虽然有效，却不便阅读。格式化后可以快速看清对象与数组的嵌套关系，适合排查请求结果或核对字段。

生成紧凑配置

编辑完 JSON 配置后，先验证语法，再压缩成系统需要的单行文本。压缩结果是 JavaScript 重新序列化生成的文本，并不保证逐字保留原文；如果字段或数字表示必须完全一致，请先查看下方限制。

区分 JSON 与对象字面量

字段名和字符串必须使用双引号，末尾不能多写逗号。验证功能可以帮助判断复制来的片段是否属于严格 JSON；底层使用 JSON.parse 按数据解析，不会当作 JavaScript 执行。

格式与功能限制

  • 这里只做严格 JSON 的格式化、验证与压缩，不会自动补引号、补逗号或修复错误，也不提供语法高亮、结构规则校验和精确行列定位。
  • 解析与序列化不是无损文本转换。重复键只会保留最后一个值；整数形式的键在 JavaScript 序列化对象时可能重新排序，从而改变属性顺序。
  • JSON 数字会转换为 JavaScript Number。超过安全整数范围时会受精度限制；数字写法也可能被规范化，例如 -0 会变成 0。如果必须保留超大数字或原始写法，请使用无损 JSON 解析器。
  • 不支持 JSON5。注释、尾随逗号、单引号字符串、未加引号的字段名、NaN 与 Infinity 都无法通过严格解析。
  • 内容需要以文本形式粘贴，没有文件选择功能。超大数据会受到当前设备内存和浏览器响应能力限制，处理大型数据集更适合使用本地命令行工具。
  • 语法有效不等于业务数据正确。日期、编号或数值即使符合 JSON，也可能不满足目标接口自己的字段要求。

常见问题

格式化会改变原始数据吗？

有可能。工具会先把文本解析成 JavaScript 值，再按所选缩进重新序列化。普通输入通常仍表达相同的业务数据，但重复键、属性顺序、大数精度和数字表示可能按上述规则改变。

能自动修复无效 JSON 吗？

不能。状态区会提示解析失败，但不会擅自插入引号、删除注释或修改逗号。这样可以避免自动修复掩盖真正的数据错误。

支持 JSON5 或 JavaScript 对象吗？

不支持。语法范围以 JSON.parse 接受的严格 JSON 为准。请先去掉注释、单引号、尾随逗号以及其他仅属于 JavaScript 的写法。

粘贴的数据会发送到服务器吗？

不会。格式化、压缩和验证都在浏览器本地执行。不过，敏感结果复制到系统剪贴板后仍可能被其他应用读取，使用完请按需清理。
