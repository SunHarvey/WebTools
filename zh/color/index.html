转换纯色表示并检查对比度

可以在 HEX、RGB 与 HSL 三种写法之间转换同一种颜色，再按照 WCAG 对比度阈值比较文字色和背景色。设计令牌、样式表和交付文档采用不同写法时，这种转换尤其方便。对比度部分只分析两个不透明纯色的数值关系，并不等于完整的无障碍审查。

颜色转换与检查步骤

  1. 填写一种受支持的颜色可输入 3 位或 6 位 HEX、三个 RGB 通道，或者 HSL 的色相、饱和度和亮度。点击对应的转换按钮后，所有字段与预览会同步更新。
  2. 读取并复制表示结果查看生成的 HEX、rgb() 和 hsl() 字符串，再复制到样式表、令牌文件或设计记录中。RGB 显示为整数，HSL 通道最多保留一位小数。
  3. 比较前景色与背景色在 WCAG 区域填写两个 HEX 颜色并开始检查，分别阅读对比度以及 AA 普通文字、AA 大字、AAA 普通文字和 AAA 大字的结果。

常见换色与检查场景

转换品牌色令牌

输入 #336699 会得到 rgb(51, 102, 153) 和 hsl(210, 50%, 40%)。当 CSS 变量使用 HEX，而设计讨论要调整 HSL 时，可以直接取得另一种写法。写法变化不会改变目标的不透明 sRGB 颜色。

整理越界通道

RGB 输入 300、127.6、-20 后会变成 255、128、0，因为每个有限数值都会限制到 0–255，再四舍五入为整数。HSL 色相 390 会按模 360 回绕成 30，饱和度和亮度则限制在 0–100。

核对正文与页面底色

可以比较 #222222 文字和 #FFFFFF 背景，再根据实际排版选择相应阈值。链接、次要文字、焦点提示和交互状态都应分别检查，不能用一组颜色代表整个界面。

输入规则与能力边界

  • HEX 只接受正好 3 位或 6 位十六进制数字，# 前缀可选，但不支持透明度。四位或八位写法会被拒绝，不会悄悄丢弃透明信息。
  • RGB 必须是有限数值，各通道先限制到 0–255，再四舍五入成整数。HSL 色相按模 360 回绕，饱和度与亮度限制在 0–100，HSL 显示最多保留一位小数。转换中的舍入会让多次往返损失小数细节。
  • 对比度采用 WCAG 相对亮度公式，判断阈值依次为 AA 普通文字 4.5:1、AA 大字 3:1、AAA 普通文字 7:1、AAA 大字 4.5:1。
  • 显示值会把计算结果向下截取到两位小数，而不是向上四舍五入。通过与否仍使用未缩短的计算结果，因此不要把界面上的边界值当成额外精度。
  • 工具不会评估真实字号、字重、透明度、渐变、图片以及悬停或禁用状态，也不会自动判断文字是否属于大字。某一颜色组合通过，并不代表页面的其他 WCAG 要求已经满足。

常见问题

HEX 前面必须写井号吗？

不必，开头的 # 可以省略，但其余部分必须正好包含三位或六位十六进制数字。三位写法会把每一位重复展开，例如 #369 会转换为 #336699。

为什么 RGB 或 HSL 输入发生了变化？

工具会把数值规范到输出能够表示的范围。RGB 通道是 0 到 255 的整数；HSL 色相被放进一个完整色环，饱和度与亮度保持在 0 到 100，并在显示时最多保留一位小数。

结果中的“大字”应该怎样理解？

阈值通常把至少 18pt，或至少 14pt 且为粗体的文字视为大字。本工具不读取实际渲染元素，因此需要根据真实字号和字重自行选择对应结果。

为什么显示的对比度采用向下截取？

这样可以避免一个略低于阈值的比值因为向上取整，看起来好像已经达标。判断逻辑使用完整比值，两位小数字符串只是便于阅读的简短表示。
