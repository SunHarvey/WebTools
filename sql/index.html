Format SQL locally, without running it

This browser-based SQL formatter makes long statements easier to inspect and can compact whitespace when you need a smaller text representation. It recognizes common clause words, operators, parentheses, quoted values, quoted identifiers, and comments so keyword casing and line breaks do not rewrite text inside strings or comments. Choose PostgreSQL, MySQL, or SQLite for the lexical rules used by common quoting and comment forms. All processing happens in this browser; the tool never connects to a database, executes a statement, or uploads your query.

How to use the SQL formatter

  1. Choose the operation and dialect.Select Format for clause line breaks and indentation, or Minify whitespace to compact layout. Pick PostgreSQL, MySQL, or SQLite to apply the corresponding common quote and comment handling.
  2. Set keyword case and indentation.Recognized unquoted SQL keywords can be uppercased, lowercased, or left as typed. The formatter supports two- or four-space indentation. Quoted identifiers, literals, and comments keep their original text.
  3. Paste, run, inspect, and copy.Use the example button for a safe sample, then run the operation and review the output. The tool does not validate database grammar or execute SQL. Clear the page or navigate away to erase temporary values from memory.

SQL formatting and minifying examples

Break a query into clauses

select id,name from users where active=true order by id is laid out with a line break before FROM, WHERE, and ORDER BY, and with list items separated onto readable lines. Recognized keywords can be capitalized without changing quoted values.

Compact without stripping comments

Minifying SELECT a, b FROM t -- keep this note removes unnecessary spaces around punctuation and collapses line layout, but retains the comment and its required line ending. Block comments, including database hints, are preserved rather than discarded.

Respect dialect-specific quoting

PostgreSQL dollar-quoted strings, MySQL backticks and hash comments, and SQLite bracket identifiers are kept intact. Choose the matching dialect when input uses these forms. The formatter does not claim to understand every vendor extension or SQL grammar.

Supported SQL subset and limits

The tool performs token-aware whitespace formatting only. It does not build a database syntax tree, validate whether a query is legal, check schema names, resolve functions, rewrite query logic, or execute statements. It supports common clause words, punctuation, comparison and arithmetic operators, single- and double-quoted text, common quoted identifiers, line comments, block comments, and selected dialect quoting such as PostgreSQL dollar strings, MySQL backticks and hash comments, and SQLite bracket identifiers. PostgreSQL nested block comments are recognized; MySQL double hyphens start a line comment only when followed by whitespace. SQL mode and session-level string settings are not configurable, including MySQL ANSI_QUOTES and NO_BACKSLASH_ESCAPES and PostgreSQL standard_conforming_strings; statements that rely on other settings may tokenize differently. Unusual procedural syntax, vendor extensions, and malformed but lexically complete statements may not receive ideal layout. Review any generated text before running it elsewhere.

Formatting normalizes whitespace and may place clauses or comma-separated items on different lines. It does not change tokens inside quoted values, quoted identifiers, or comments. Keyword casing applies only to recognized unquoted words; an unquoted identifier that happens to match a reserved keyword may also be recased. The minifier retains comments and quoted text because comments can contain optimizer hints or other meaningful directives. The minifier preserves whitespace before each opening parenthesis as entered; in some dialects or SQL modes that space can affect function-name parsing. Minification is not encryption, obfuscation, or a guarantee of equivalent behavior for every database mode.

Raw input is limited to 250,000 characters, tokenization to 50,000 tokens, parenthesis nesting to 100 levels, and output to 500,000 characters. These independent bounds limit browser work and generated text; they do not guarantee instant processing on every device. The input is not written to local storage, session storage, cookies, a server log, or recent-tool history. Temporary input and output are cleared when leaving the page and when a page is restored from browser history.

This page is a text formatter, not a secure SQL execution environment. Do not use it to run database commands, and do not treat formatting as a review of permissions or query safety. SQL remains in the page unless you explicitly copy it yourself.

SQL formatter FAQ

Does this tool execute or validate my SQL?

No. It only tokenizes text to format whitespace and recognized keyword case. It does not connect to a database, execute statements, validate schema names, or guarantee that a query is syntactically valid.

Which SQL dialects are supported?

Choose PostgreSQL, MySQL, or SQLite for common lexical differences in comments and quoting. This is not full vendor grammar support; unusual extensions and procedural SQL may not format ideally.

Does minifying remove comments?

No. Line comments and block comments are preserved, including optimizer hints. Line-comment endings are kept so following SQL does not become part of the comment.

Is my SQL uploaded or saved?

No. Formatting and minifying run locally in your browser. The page does not send SQL to a server or third-party API, does not store it in browser storage or recent-tool history, and clears temporary values on navigation.
